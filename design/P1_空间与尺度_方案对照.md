# P1 空间与尺度：三版灰模对照（方案书）

> 依据：`11_城市规模与建筑体系重建_AI执行方案.md` §P1。
> 目的：在动手做 P3/P4 之前，用**灰模（`?grey=1`）**把"规划与尺度"定死，
> 避免继续在错误的空间骨架上堆建筑。

## 0. 测量口径（冻结，不改）

| 指标 | 口径 | 现状值 |
|---|---|---|
| 主街宽 | 朱雀大街/横街的路面格数（城体素） | ZHUQUE 10、HENGJIE 16 |
| 次街宽 | MAIN 5、GATE8 8 | — |
| 巷宽 | WARD_CROSS 2、LANE 1 | — |
| 坊内分划 | 大坊四门十字街 + 四象限；小坊一字横街 + 两带 | — |
| 宅地进深 | 院落南北向格数（含院墙） | 单进为主 |
| 建筑占地率 | 坊内建筑投影 / 坊面积 | 偏高（屋脊连片） |
| 屋脊连续度 | 沿街可见独立屋顶轮廓数 / 100 格街面 | 未测 |

**判定机位（固定，全部灰模、noon、seed `5a17c4a9`、1600×900、q=mid）**
- `axis`：中轴鸟瞰（判街—坊—院等级）
- `wardGate`：坊门街景（判街宽与门内纵深）
- `lane`：坊内巷道（判院落肌理与巷两侧围合）

## 1. 方案 0（现状对照，`验收截图/p1_grey0`）

灰模诊断（三机位 6/10）：
- **街道等级读不出**：主轴最宽、其余宽度层级单一，十字街/巷级差几乎不可辨。
- **院落纵深浅**：多为单进，门内一进即止；院与院不成嵌套，屋脊连成整片。
- **坊内方块感**：坊格未显，呈"沿街房 + 方块堆叠"。

## 2. 方案 A：现状骨架 + 尺度校正（最小改动）

- 保持 108 坊与中轴不动。
- 只做两件事：① 巷宽 `LANE` 1→2、`WARD_CROSS` 2→3，让巷可辨；
  ② 单进宅地统一加深 1 进（前院—正房—后院），进深下限抬到可容纳两进。
- 预期：街道等级与院落纵深各改善一档；改动风险最低，但"方块感"仍在。

## 3. 方案 B：增加院落纵深与道路层级（推荐）

- **道路三级**：主街（ZHUQUE 10 / HENGJIE 16）→ 十字街（2→4）→ 巷（1→2）。
  级差比约 5:2:1，灰模下必须一眼看出三级。
- **坊内两级分划**：大坊四象限 → 每象限再分 2×2 宅地组团，组团间留支巷（1 格）。
- **宅地进深**：普通宅地 2 进（前堂后寝），大宅地 3 进（穿廊）；
  进深不足的宅地宁可减少数量，不压缩进深（**宁可少、不可浅**）。
- **围合**：沿巷两侧以院墙连续围合，禁止"孤立方块"直接临巷。
- 预期：坊格、巷网、院落嵌套三者同时可读；代价是建筑总数下降（预算按 §5 兜底）。

## 4. 方案 C：扩大组团（激进）

- 坊内改为 2×2 大组团 + 组团内支巷；宅地统一 3 进；
- 沿街只留"组团门面"，内部以连续屋脊 + 院墙织成肌理。
- 预期：远景屋脊肌理最好看；但单体可辨识度下降，与 P2"每栋单拉出来够看"冲突，
  且建筑数下降最多。

## 5. 对照与取舍规则

1. 三版必须用**同一组固定机位、同一 seed、同一灰模**渲染，不得换机位找好看的角度。
2. 判定三问（每问须"是"）：
   - 主街 / 十字街 / 巷的宽度级差在灰模下能否一眼分辨？
   - 能否看出"坊 → 组团 → 院落 → 单体"四级嵌套？
   - 沿街是否形成连续围合（而非孤立方块排列）？
3. 若 B 与 C 均满足三问，取建筑数下降较少者；若都不满足，回到参数重做，**不降标准**。
4. 选定后写进 `design/尺度与预算表.md` 作为 P3/P4 的硬约束（含建筑数下限）。

## 6. 实施方式

- 用查询参数 `?plan=0|A|B|C` 切换规划参数（默认 = 选定方案），保证可复现对照。
- 每版渲染 `axis` / `wardGate` / `lane` 三机位灰模 + 一次彩模，存 `验收截图/p1_<方案>/`。
- 视觉判定用同一套问题、同一模型，评分口径不随方案调整。

## 7. 实施记录

### 第 1 轮对照（`验收截图/p1_grey0|p1_A|p1_B|p1_C`）

参数已落地（`?plan=0|A|B|C` → `CFG.PLAN_TABLE` → `CHANGAN.PLAN`）：

| 方案 | cross（十字街宽） | branch（支巷） | 建筑数 | checksum(seed 5a17c4a9) |
|---|---|---|---|---|
| 0 | 2 | 无 | 417 | 3bd1b57e |
| A | 3 | 无 | 415 | a47aca3d |
| B | 4 | 有（plotMin 25） | 410 | bb20891 |
| C | 5 | 无 | 404 | 5d4707b9 |

灰模三机位视觉均分：**0 = 6.3 / A = 6.7 / B = 7.0 / C = 6.7**。

**判定结论：三问未通过，不得定案。**
- 问 1（街道级差一眼可辨）：**四版全部失败**。每个机位都判"级差难以一眼分辨"——
  十字街 2→5 的变化相对主街 10 太弱，且固定机位不同框（`lane` 只见巷、`axis` 只见主街）。
- 问 2（坊→组团→院落→单体嵌套）：多数视角判"层次模糊"，仅 C 的 `lane` 明确读出。
- 问 3（沿街连续围合）：多数视角通过（连续坊墙/街墙）。

**两条硬约束（实测得出，写进 P2/P3 前提）**
1. **坊深不足**：坊深 37 城体素 → 象限深 16 < 宅地最小进深 12×2。
   因此"象限内切两排宅地"在现有坊格下不可能（B 的支巷处于休眠状态）；
   要做出两进院落，必须先**加深坊格**（减少排数或向南扩展坊区），或改用整坊两带。
2. **级差要跨机位同框**：判定机位必须能同时看到主街 / 十字街 / 巷，否则问 1 无法回答。

**下一轮迭代方向**
- 参数：`cross` 提到 6（主街:十字街:巷 = 10:6:2，比例 5:3:1），必要时把巷压到 1；
- 机位：新增"坊角鸟瞰"（同框主街 + 十字街 + 巷 + 院落）；
- 若仍不通过，动坊格本身（ROWS 9 排 → 6 排加深，或坊区南扩），并重跑 108 坊计数审计。

## 8. 第 2 轮对照与定案（第 11 轮）

**新增判定机位 `wardCorner`（坊角鸟瞰）**，解决问 1 的"不同框"问题：
斜俯角把主街、坊内横街、巷、院落收进同一帧。参数同步调整为
`0: cross 2 / A: cross 3 / B: cross 5 / C: 横街 5 + 整坊两带`。

**三问复判（灰模，四机位）**

| 方案 | 建筑数 | wardCorner | 三问 |
|---|---|---|---|
| 0 | 417 | 7/10 | 全过 |
| A | 415 | 6/10 | 问 1 不过 |
| B | 404 | 6/10 | 问 1 不过 |
| C | 404 | 7/10 | 全过 |

绝对评分差异在噪声内（6.0~6.5），故按 §5 追加**两两对照**（同一 agent 同看两版，必须选优）：

- `0 vs B` → **B 胜**（街道级差 / 嵌套 / 城市感三项全胜，置信中）
- `0 vs C` → **C 胜**（三项全胜，置信中）
- `B vs C` → **C 胜**（三项全胜，置信中）

**定案：方案 C「整坊两带」。** 已写入 `design/尺度与预算表.md` §六 作为硬约束；
默认值切换为 C（`?plan=` 缺省 = C，`PLAN=0|A|B` 仍可复现对照）。
方案 C 实测：建筑 404 / 400 / 384（三个 seed，均 ≥ N0 375），12 项审计全绿。

**已知代价**：C 取消坊内南北纵街（史实大坊为四门十字街）。保留补救路径：
若 `wardGate` 机位暴露坊门不通/纵深不足，补一条 1~2 宽的南北巷（仍远低于横街 5）。
