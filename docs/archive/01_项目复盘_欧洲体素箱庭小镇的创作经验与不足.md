# 《欧洲体素箱庭小镇》项目复盘：创作经验与不足

> 复盘对象：`欧洲体素箱庭小镇/index.html`（单文件约 2.67 MB、6.6 万行，内联 Three.js；历经 192→320→384→1024 多轮扩城，含 VALDORA 大陆、36 种住宅原型、18+ 巡游机位、动态船队/市民、第一人称漫游、小地图、涂抹编辑、昼夜引擎等）。
> 用途：为下一个项目《唐长安城体素箱庭》提供"该继承什么、该规避什么"的清单。结论全部来自源码与项目自带文档（《性能优化与升级建议.txt》《全项目地基系统重做提示词》《城市规划与建筑升级提示词》等），行号/标识符以当前源码为准，新项目执行时需自行复核。

---

## 一、项目做对了什么（可直接继承的方法论）

### 1. 数据底座：统一体素模型 + 稀疏存储
- 全场景统一 1×1×1 体素，31 位整数键（x/z/y 位打包）+ `Map` 稀疏存储，TypedArray 承载 `heightField / groundType / roadNetwork / footprint / parcel` 等字段层。
- 体素只存"颜色编号 + 少量语义标志位"，颜色走调色板；几何靠 `InstancedMesh` 按颜色合批，从根上压住 draw call。
- 经验：**字段层（高度/路网/地块）与体素层分离**，是后面所有精修、审计、编辑功能能成立的前提。

### 2. 确定性程序化生成：种子驱动，禁止随机
- 全局种子经 hash 派生各级子种子；禁止裸 `Math.random()`；同一 seed 必须逐体素可复现。
- 建筑用"参数签名"去重：同原型两栋楼的屋顶/窗带/配色必须不同，杜绝 Ctrl+C 感。
- 多种子（至少 3 个）回归验证作为验收项，checksum 比对。

### 3. 分阶段生成管线 + 主线程让帧
- 管线顺序：地形骨架 → 路网 → 城墙 → 地标占地 → 大道 → 住宅地块 → 建筑 → 立面精修 → 细节 → 封壳 → 全域审计 → 实例化。
- 阶段之间 `yieldSlice / nextFrame` 让出主线程并刷新进度条，避免白屏假死（注意：这只是"让帧"，不是把计算搬出主线程，见不足第 2 条）。

### 4. 地形与城市的"自然生长"方法（欧洲镇的核心资产）
- 地形：fBm 噪声 + domain warp + 海拔带连续分类 + 坡度材质；"表壳 + 侧壁 + 稀疏地质骨架"代替实心填充，体内体素剔除。
- 台地工程：挡墙、扶壁、台阶化处理，建筑落在开挖/填筑后的平台上而不是悬空。
- 城市：分区多边形 → A* 路网（带坡度/转弯惩罚）→ 沿街 burgage 地块细分 → 参数化原型建筑（36 种 massing generator）。
- 建筑语法：局部 (u,v) 坐标 + 90° 旋转统一映射；屋顶 assembly（gable/hipped/cross/spire）；立面精修（门窗退进、边框、层带、山墙封堵）。

### 5. 防浮空的"构造 + 审计"双保险（花了两轮大返工换来的）
- 构造期：每个构件必须带锚点，动态构件（悬索、拱、旗帜）记录扫掠体。
- 构造后：全域 6 邻域基岩泛洪（bitset + Int32 队列，禁止递归爆栈），把"与基岩不连通"的体素判为 fatal，而不是再造东西遮住。
- 教训沉淀为制度：**不允许"造了再遮"的补丁式修复**。

### 6. 性能工程的有效手段
- InstancedMesh 按色合批、顶点 AO、Lambert 材质、分块显隐、阴影手动 `needsUpdate`、DPR 封顶、质量分级自动降级。
- 硬预算（体素数/批次数上限）+ `acceptanceChecks` 断言表，超限直接 fatal 而非带病交付。

### 7. 体验层的完整度（这是项目最出彩的部分）
- 18+ 巡游机位（VIEWS）+ LORE 数据卡片，每个机位有标题、正文、构图意图；
- 街巷第一人称漫游（WASD、碰撞、地面高度缓存）；
- 动态生活层：船队、市民（实例矩阵动画）、粒子（炊烟/水雾/泡沫）；
- 昼夜引擎 + 程序化 Web Audio（零外部音频文件）；
- 小地图（全局/雷达两档）、涂抹编辑（localStorage 持久化 + 撤销重做）、光照模式切换、拍照 PNG、URL 分享（seed + 相机 + 光影编码进 URL）。

### 8. 工程纪律
- 离线单文件：vendor 内联 three.js，CSP 锁死，零外部请求，`file://` 双击即开；
- spec 先行 → 样段验证 → 再全城铺开；每轮备份 + SHA256；自审否决项清单；
- 验收必须包含"不同于生成路径的回读"和真实入口（file://）测试。

## 二、项目暴露的不足（新项目必须前置规避）

### 1. 规模一路失控，架构没有随规模演进
- 世界从 192 扩到 320、384、1024，体素预算抬到 460–520 万；仍是"一体素一实例立方体 + 256 大块剔除"的老架构，剔除粒度对大城无效；冷启动 60 秒级、内存尖峰白屏。
- **新项目对策**：先定世界尺寸与体素/实例硬预算，再反算每个系统的配额；规模与架构同步设计，禁止"先扩了再说"。

### 2. 生成全压主线程，让帧不等于并发
- `yieldSlice` 只保证不白屏，数百万 Map 写入的总时长、内存峰值一点没少；没有 Worker、没有预烘焙、没有 LOD。
- **新项目对策**：重计算进 Worker（或可序列化的离线生成阶段）；远景走低模 LOD / 合并网格；把"生成耗时、峰值内存"写进验收表。

### 3. 补丁叠加，多套规划 pass 并存
- V2/V3/V5/V6/V7/V8 规划层互相叠加，"造了再遮住"反复出现；单文件膨胀到 6.6 万行，解析编译本身就有成本。
- **新项目对策**：每个空间事实只允许一个权威来源；新 pass 上线必须替换而非叠加旧 pass；模块按节清晰分区，定期合并死代码。

### 4. 视觉返工集中在"缺总图、缺样段"
- 规则阵列像停车场、小塔/尖顶滥用导致重音过密、地表高频噪声、台地像层层蛋糕、外岛像环形展台——这些都靠后期一轮轮重做。
- **新项目对策**：开城前先出"总图规则 + 1/4 样段"，确认肌理、重音节奏、配色、标高语言后再铺开；重音地标做配额管理。

### 5. 每帧系统不分频，HUD 成本失控
- 市民、船队、小地图、射线检测全部每帧全量跑；`backdrop-filter: blur` 的 HUD 在百万实例场景下加剧发粘；电影档后处理（PCF 2048 阴影、ACES、DPR 1.35）默认开启，降级是事后补救（draw call ≥260 才关投射）。
- **新项目对策**：动态系统按距离/重要性分频更新；画质档位在开城时实测帧率预选，而不是卡了再降；HUD 禁用大面积模糊。

### 6. 验收口径出现过"估算冒充实测"
- 曾用 localhost 结果冒充 file:// 直开、把估算写成"已达标"、只截鸟瞰图而漏掉行人视角碰撞问题。
- **新项目对策**：file:// 直开为唯一准入口径；性能数字必须实测填表；鸟瞰 + 行人 + 机位三视角都要留证。

### 7. 题材层面的特定风险（唐长安项目尤其要警惕）
- 欧洲项目曾把不同地域/年代的名胜拼在一起，产生"主题公园感"和年代混杂（如晚期火车站混入中世纪镇）。
- **唐长安对策**：锁定单一时间断面（建议开元—天宝盛唐），建立"年代白名单/黑名单"：乌头门是唐的、石牌坊是明清的（不做）；坊市制下临街不得开店（店只在东西市内与特许坊内）；不做满铺琉璃瓦（宫殿剪边/鸱尾用琉璃，民居青灰瓦）。

## 三、给唐长安项目的一句话总纲

> **欧洲镇的成功在"自然生长"，唐长安的灵魂在"先规划后建设的礼制棋盘"——生成逻辑要反过来：先立中轴线与经纬网格，再让生活在坊内生长；用完整 108 坊的"格局"立骨架，用 20–30 个名坊的"细节"立血肉；规模、预算、画质档位、样段验证全部前置，不让欧洲项目的任何一轮返工在长安重演。**
