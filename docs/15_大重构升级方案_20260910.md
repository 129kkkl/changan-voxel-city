# 15 大重构升级方案（2026-09-10）

> 依据：`14_项目审计报告_20260910.md`。审计结论是**表示层失败**，不是美术参数不足。
> 本方案的目标不是"再修一轮"，而是**换掉决定画面上限的那几层**，并把验收闭环重建，使"自评通过、用户否定"的循环无法再发生。
>
> 阅读提示：本文是**施工图**，不是愿景书。每个阶段都有可证伪的退出条件；未达条件不得进入下一阶段。

## 零、目标与判定标准（先冻结，事后不得下调）

### 0.1 目标

一座**落在完整地域环境中的、可以走进去细看的盛唐主题微缩都城**：
远景有城郭、轴线、宫殿与城区的巨大秩序；中景有连续而富于变化的坊巷、院落与屋顶；近景有清楚的建筑构造、舒适的比例、真实的材质与空间厚度。

### 0.2 判定标准（三层，缺一不可）

| 层 | 标准 | 工具 |
|---|---|---|
| **硬不变量** | 每条都可自动判定真假（见 §4.1） | `tools/visual-gate.js` |
| **视觉门** | 独立视觉模型评审：均分 ≥ 7.5、无单张 < 6.0、blocker 缺陷清零 | `tools/visual-gate.js` |
| **用户判断** | 用户看过最终截图/实机后认可 | 人工 |

> **禁止自评分数。** 执行方不得给出"完成度评分"。所有分数只能来自独立评审工具与用户。
> **禁止以"比旧版更好"作为完成依据。** 唯一参照是 §0.2 的绝对标准。

### 0.3 明确不做的三件事

1. **不缩场景换质量**：城市规模、108 坊、主要地标、种子复现、漫游、编辑、离线单文件全部保留。
2. **不再用体素表示建筑**：建筑改用语义化程序网格；体素只保留给城市骨架与地表（见 §1 D1）。
3. **不再靠参数调优修补**：屋顶台阶、材质缺失、无 AO 这三件事必须在表示层解决，不得用"加一层构件/换一组配色"掩盖。

## 一、五个架构决策（本方案的骨架）

### D1 — 建筑表示：从体素改为**语义化参数模型 → 程序化网格**

**现状**：建筑是 4× 细分体素（1 格 = 3.45 m），斗拱/瓦垄/窗棂在数学上无法表达（审计 R1）。
**决定**：建筑由 `BuildingSpec`（语义描述，单位为米）驱动，由构件库生成**多边形网格**。

- 屋顶是**连续曲面**（由举折曲线 + 翼角起翘参数化），不是台阶；
- 斗拱、窗棂、瓦垄、椽头是**几何或实例化模块**，可按 LOD 增删；
- 同一份 spec 派生：渲染网格、碰撞体、拾取盒、LOD——**单一权威，无第二套几何**。

**为什么不是"提高体素分辨率"**：要表达 0.3 m 构件需 `ARCH_S ≈ 46`，体素数膨胀约 1500 倍（5.67M → 85 亿），内存与网格化时间均不可行。体素表达在"全城 × 构件级"这个组合下不成立。

### D2 — 尺度：**米制为唯一权威**，重建三级细分

**现状**：地块 165~360 m，一坊 2~6 个建筑群（审计 R2）。
**决定**：全局以米为单位（`PX_PER_M` 单一常量做场景换算），重建：

```
坊 (500~560 m)
 └ 街区 band（十字街/一字街 15~25 m 分隔）
    └ 巷 lane（5~8 m）
       └ 宅地 plot（面阔 15~40 m × 进深 30~80 m）
          └ 院落 compound（1~4 进）
             └ 单体 building（正房 / 厢房 / 门屋 / 后罩 / 倒座）
```

每坊宅地数 **40~80**，全城建筑群目标 **5,000~8,000**（现 387）。

### D3 — 渲染：重建材质、光照与大气

**现状**：3 个顶点色 Lambert 材质、单张 4.4 m/texel 静态阴影、无 AO、无后处理（审计 R3）。
**决定**：程序化纹理图集 + `MeshStandardMaterial` + 逐顶点 AO + 3 级级联阴影 + 天空 IBL + 高度雾 + 轻量后处理。

### D4 — 验收：**独立评审 + 硬不变量 + 回归基线**

**现状**：12 项结构审计全绿、视觉自评 8.34、独立 4.56（审计 R5）。
**决定**：`tools/visual-gate.js` 成为**构建的一部分**，不过门即视为构建失败。

### D5 — 工程：**一套建筑生成器**，删除全部补丁层

**现状**：4 套建筑生成器 + `g09_refine` 后置覆盖 `g08_arch` + 死代码 + 19 份互相矛盾的文档（审计 R6）。
**决定**：合并为一套 spec builder；删除 `g04_fine.js`、`g04_proto.js` 的建筑分支、`g09_refine.js` 的 monkey-patch；文档收敛为 4 份。

## 二、目标架构

### 2.1 分层与单一权威

```
┌───────────────────────────────────────────────────────────────┐
│ L4 表现层   render/  材质 · 光照(CSM+IBL) · 天空 · 雾 · 后处理  │
├───────────────────────────────────────────────────────────────┤
│ L3 生活层   prop/    植被 · 行人车马 · 摊铺旗幌（实例化）        │
├───────────────────────────────────────────────────────────────┤
│ L2 建筑层   arch/    BuildingSpec → 构件库 → 网格/碰撞/拾取/LOD  │  ← 唯一建筑权威
├───────────────────────────────────────────────────────────────┤
│ L1 骨架层   city/    城墙城门 · 街道 · 坊墙 · 渠桥（体素）        │
├───────────────────────────────────────────────────────────────┤
```

**铁律（继承并强化原有守则）**：

- 每层只有一个权威数据源；下层不得生成上层会重复生成的内容。
- **建筑只能由 `arch/` 生成**；`city/` 与 `terrain/` 不得写入任何建筑体素。
- 渲染、碰撞、拾取、编辑、LOD **全部由同一份数据派生**，禁止第二套几何。
- 禁止任何"先生成 A 再用 B 盖住 A"的写法（含函数级 monkey-patch 覆盖）。

## 三、关键子系统设计

### 3.1 `BuildingSpec` —— 建筑的唯一权威

```js
/**
 * 单位：米。origin 为台基中心在地面的世界坐标；yaw 为朝向（弧度，0 = 面南）。
 * 所有字段必须可序列化，以便存档/编辑/回归复现。
 */
{
  id: 'w037/plot-12/main',
  kind: 'house'|'shop'|'office'|'temple'|'palace'|'gate'|'pagoda'|'pavilion',
  rank: 0..5,
  origin: { x, z, yaw },

  platform: { tiers, height, mold, edgeColor, steps: { side, width, run, sideStones } },
  bays:     { count, width, depthCount, depth },      // 开间 / 进深
  columns:  { radius, height, color, plinth: { h, style } },
  walls:    { height, thickness, color, baseH, baseColor,
              openings: [ { bay, type:'door'|'window'|'lattice', w, h, sill } ] },
  bracket:  { present, perBay, arm, height, color },  // 斗拱
  roof:     { form:'hip'|'xie'|'xuan'|'zan'|'double',
              pitch, curve, overhang:{eave,gable}, upturn,
              ridge:{ h, chiwei:'none'|'small'|'large' },
              tile:{ color, groove, ridgeColor, trim } },
  railing:  { present, style },
  courtyard:{ enclosure:{h, cap}, gate:{type, w, h}, paving, well, trees }
}
```

**校验器 `validateSpec(spec)`**：在生成前拦截非法组合（如 `bays.width < 2*column.radius`、`roof.pitch > 0.7`），把"美术错误"变成"构建失败"。

### 3.2 屋面生成器（本项目最关键的一段代码）

```
输入：屋面轮廓（檐口线）+ 脊线 + 举折曲线 + 起翘参数
输出：连续三角网格 + 解析法线

参数域：
  u ∈ [0,1]  沿屋脊方向
  v ∈ [0,1]  檐口 → 屋脊

高度：   h(u,v) = ridgeH * pow(1 - v, 1/curve)                 // 举折：底缓顶陡
平面：   P(u,v) = lerp( EaveLine(u), RidgeLine(u), v )
起翘：   + upturn * smoothstep(0.72, 1.0, |2u-1|) * (1-v)^2     // 翼角，仅檐角附近
瓦垄：   LOD0 —— 沿 u 每 TILE_PITCH(≈0.32 m) 一条半圆垄（几何）
        LOD1+ —— 纹理图集
```

**硬约束**：屋面高度剖面沿 v 必须**单调递增**，相邻采样高差 ≤ 0.35 m。这条由 `visual-gate` 自动检查，直接消灭"千层糕/台阶屋顶"。

### 3.3 构件库 `b02_parts.js`

| 构件 | LOD0 | LOD1 | LOD2 |
|---|---|---|---|
| 台基 | 须弥座线脚 + 压面石 + 踏跺 + 垂带 + 栏板 | 台基体 + 踏步 | 台基体 |
| 柱网 | 圆柱 + 柱础 + 阑额 + 普拍枋 + 雀替 | 方柱 + 额枋 | 方柱 |
| 墙 | 墙体 + 下碱 + 开洞 + 窗棂 alpha 面 + 门框门扇 | 墙体 + 开洞 | 墙体 |
| 斗拱 | 栌斗 + 华拱 + 令拱 + 散斗 + 撩檐枋（实例化模块） | 简化块 | 檐下暗带 |
| 屋面 | 曲面 + 瓦垄几何 + 垂脊 + 戗脊 | 曲面 + 瓦垄纹理 | 曲面 |
| 脊饰 | 鸱尾（按 rank 分三档） | 简化鸱尾 | 无 |

**柱径 / 开间比**：硬性约束在 `[1/12, 1/8]`（真实唐构约 1/9~1/11）。这条直接消灭"火柴棍柱子"。

### 3.4 材质与纹理（`b11_atlas.js` / `r02_materials.js`）

- **程序化纹理图集**：运行时用 Canvas 生成 9 种材质（瓦/琉璃瓦/木/粉墙/砖/石/夯土/草/水），无外部资源，保持离线单文件。
- 每种材质含 albedo + roughness（+ 可选 normal 由 albedo 派生）。
- `MeshStandardMaterial` + `scene.environment`（天空 IBL）。
- **逐顶点 AO 烘焙**：由几何邻域 + 檐下遮挡计算，建筑层必须有 AO（当前完全没有）。
- 目标：单张画面色数从 ~150 提升到 **≥ 800**（`imgstat` 可测）。

### 3.5 光照与大气（`r03_lighting.js` / `r05_fog.js` / `r06_post.js`）

- **太阳**：`DirectionalLight` + **3 级级联阴影**（0–40 m / 40–160 m / 160–600 m），近级 2048² → **0.02 m/texel**（当前 4.4 m/texel）。阴影相机跟随视角中心。
- **天空 IBL**：现有天空 Shader → `PMREMGenerator` → `scene.environment`，替换 hemi/amb 常量（当前环境光占太阳 49%，导致无对比）。
- **雾**：高度雾 + 空气透视（远处按天空色去饱和，而非刷白）。禁用"靠雾掩盖未完成区域"。
- **后处理**：曝光/ACES（已有）、轻 bloom、高画质可选 SSAO。禁止用暗光、浓雾、过曝掩盖几何缺陷。
- 正午自然光下必须成立（这是主要验收光照）。

### 3.6 城市细分（`city/y03_wards.js` 重写）

```
坊 500~560 m
 ├ 主街 / 十字街 / 一字街（15~25 m）
 ├ 街区 band（进深 100~200 m）
 │   ├ 巷（5~8 m，铺巷概率按区位）
 │   └ 宅地 plot（面阔 15~40 m × 进深 30~80 m）
 └ 公共节点：寺观 / 官署 / 园林 / 场院 / 井台
```

- 布局家族按区位与等级分配：密居民居 / 府第 / 官署 / 寺观 / 市肆 / 园林 / 仓储作坊。
- **宅地尺度必须落在真实量级**（15~40 m 面阔），这是"街—巷—院"三级空间成立的前提。
- 建筑群数量目标 **5,000~8,000**；不得靠删减换质量，也不得用零碎构件凑数。

### 3.7 生活层（`prop/`）

- **植被**：乔木（主干 + 分枝 + 叶簇体量）/ 灌木 / 竹林 / 松柏，按群落疏密分布，禁止单一克隆体等距排列。
- **人物 / 车马**：`a03_life.js` 已有约 200 个实例的 ActorSystem，**问题不是没有，而是看不见**（1.5 城市格高，远景机位 1~3 像素）。改造方向：① 在行人尺度机位保证近景有可辨的人物与车马；② 提高主街、市场、城门的人流密度；③ 增加摊铺、货担、旗幌等"体量更大、更可读"的市井物件。
- **摊铺 / 旗幌 / 灯笼 / 货箱**：市场必须"市"起来。
- 全部走 `InstancedMesh`，单实例三角形数 ≤ 200。

### 3.8 LOD 与性能预算

| 项 | 目标 | 现测 |
|---|---|---|
| 视锥内三角形 | ≤ 1.2 M | 最高 1.27 M（单景），但**预算审计未统计** |
| Draw call | ≤ 120 | 12~157 |
| 建筑分块 | 64 m（视锥裁剪粒度） | 880 m（过粗） |
| 冷启动 | ≤ 30 s | 20.7 s |
| 内存 | ≤ 1.2 GB | 未测 |
| **桌面 GPU 帧率** | **1600×900 中画质 ≥ 45 FPS（实测）** | **未测** |

- LOD：L0（近，<60 m，全构件）/ L1（60–180 m，去斗拱瓦垄几何）/ L2（180–500 m，屋面平面 + 体块）/ L3（>500 m，合并剪影）。
- 切换用滞后阈值避免跳变；**走近必须恢复 L0**。
- **预算审计口径必须改为"全图层总量"**（city + arch + prop），修掉审计 R4。

## 四、验收闭环（`tools/visual-gate.js`）

**这是本方案中优先级最高的一项。** 没有它，第 8 轮仍会重演。

### 4.1 硬不变量（每条自动判定，失败即构建失败）

| # | 不变量 | 判定方式 |
|---|---|---|
| H1 | 屋面非台阶 | 沿坡面采样高度剖面，单调且相邻高差 ≤ 0.35 m |
| H2 | 屋顶坡度合理 | 18° ≤ 坡度 ≤ 32° |
| H3 | 出檐合理 | 0.8 m ≤ 出檐 ≤ 2.5 m |
| H4 | 柱径/开间比 | ∈ [1/12, 1/8] |
| H5 | 每栋建筑有台基/柱/墙/屋面 | spec 完整性校验 |
| H6 | 无未贴图表面 | 每个材质必须引用图集条目 |
| H7 | 地面无大面积同色 | 连续同色区域 > 200 m² 必须有材质变化或铺装 |
| H8 | 无浮空 / 无穿模 / 无过窄建筑 | 几何检查，宽 < 3 m 的建筑拒绝生成 |
| H9 | 建筑数量下限 | 全城建筑群 ≥ 5,000 |
| H10 | 预算（全图层） | 三角形 / draw call / 内存 / 生成时间 |
| H11 | 街道有活动 | 每 100 m 主街至少 N 个人物/车马实例 |
| H12 | 类型学覆盖 | 每种建筑类型与来源都走新 builder，无旧路径残留 |

### 4.2 视觉门（每次构建）

- **固定机位集**：原 18 景 + 新增 8 个体验机位（城外入城、城门内外、普通坊俯瞰、住宅入口、院内、市街地面、官署/寺观、水岸），共 26 景。
- **独立评审**：视觉模型逐图打分 + 挑错（**不告知项目自评分**）。
- **通过条件**：均分 ≥ 7.5、无单张 < 6.0、blocker 缺陷清零。
- **回归**：与上一版同机位像素 diff，任何机位均分不得下降。

### 4.3 证据与归档

每次构建产出 `验收截图/<tag>/`：26 张 PNG + `report.json`（分数、缺陷、fps、三角形、draw call、渲染器、时间）+ `gate.json`（硬不变量逐项结果）。

## 五、分阶段施工计划

> 每阶段：目标 → 任务 → **退出条件（可证伪）** → 风险。
> **未达退出条件不得进入下一阶段。** 质量不足时继续改生成器，不降低标准。

### P0 清场与基线（0.5~1 天）

**目标**：把地基清干净，建立不可作弊的基线与门。

任务：
1. 文档收敛：19 份 md → `docs/archive/`（历史提示词/诊断/阶段报告全部归档）；根目录只留 `README.md`、`SPEC.md`、`验收标准.md`、`CHANGELOG.md`。

| 风险 | 影响 | 对策 |

## 八、如果只能做一件事（降级方案）

若无法投入完整重构，**唯一值得做的是 P1 + P2 的最小版**：只把**屋面**换成连续曲面、把**材质**换成程序化图集、给建筑层加 **AO**。

预期收益：独立评分从 4.56 提升到 **6.0~6.5**（消除评审 Top 1/3/4 三项）。
**但这不足以达标**——审计 Top 2（无木构体系）与 Top 5/7/9（无肌理、无等级、无多样性）由 D1/D2 决定，不换表示层与尺度就永远解决不了。**不推荐以此交付。**

## 九、第一个 72 小时的具体动作

按顺序执行，不做完不进入下一步：

1. **打 tag 与备份**：`git tag pre-refactor-20260910`；确认工作区干净。
2. **建立基线**：跑 `visual-gate --tag baseline`，确认基线分 4.56 与 blocker 清单落盘。
3. **文档收敛**：15 份历史 md → `docs/archive/`；写 `验收标准.md`（§0.2 + §4 全文）。
4. **代码归档**：`g04_fine.js` 与 `g09_refine.js` 移入 `src/_legacy/`，确认构建仍通过、18 景画面不变（作为"零行为改动"验证）。
5. **写 `core/c01_units.js`**：定义 `PX_PER_M`、米制常量、`metersToScene()`，并让现有代码先引用它（为 D2 铺路）。
6. **写 `arch/b01_spec.js` + `b03_roof.js` 的灰模版**：只做屋面曲面 + 举折 + 起翘，无材质无细节。
7. **建一座灰模民居**，用 `shot.js` 的 `--solo` 拍 4 视角，独立评审打分。**若灰模比例不成立，继续改原型，不要开始批量生成。**

> 完成第 7 步后，再决定 P1 是否继续、以及是否需要调整 spec 字段。**不要在灰模未通过前写材质和光照。**

## 十、与历史方案的关系

本方案**不继承**此前 7 轮的"修补式"路线（v1 屋面重写 → v2 台阶坡 → v3 放大规模 → P1~P6 分阶段 → M2 双尺度 → 提示词 12 → 提示词 13）。理由见审计报告 §十一：这些轮次的共同点是**都在体素表示层内调参**，而瓶颈正是这一层。

本方案**继承并保留**审计报告 §十列出的全部可用资产（城市骨架、管线、确定性、离线交付、工具链、机位）。
